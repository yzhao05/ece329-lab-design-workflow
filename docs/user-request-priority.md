# 两种模式的用户请求优先级修复

检查范围：`GUIDED_DESIGN`、`EMVR_DIRECT`，包括 EMVR 公式入口、阶段确认和最终输出。

原先并未完全做到用户请求优先。主要问题包括：

- 只有 EMVR 的提问/纠错会压住部分推进信号；引导模式和 `complete_stage` 按钮仍有先推进的路径。
- 参考、审阅、总结和课程提问使用互斥回复分支，一轮多个请求可能只完成一个，任务记录却全部标成完成。
- “只能处理当前阶段”的提示及阶段产物校验限制了课内追问；阶段一后处理还能将已经生成的回答改写成大纲。
- 本地模板降级回复也被记作“已回答课程问题”。

现在两种模式共用请求优先检查：先提交明确的设计修改，再分别响应课内提问、参考、总结、审阅和版本请求。含这些请求或未理解片段的回合暂停推进/返回及自动完成，按钮不能绕过检查；问题处理后可从原进度继续。完整修复已写总结的终态纠错仍可直接完成，无须追加空确认。

课程回答按本轮写入后的设计生成，并独立于参考或审阅呈现；不会把提问、纠错或生成的临时阶段草稿写入学生设计。参考可更新同阶段的采纳入口。未理解片段只请求局部澄清，已经明确的修改保留。

生成层为课内提问和参考使用独立回复契约，允许跨阶段提问，不要求提交当前阶段整套产物，也不执行阶段一大纲改写。引用仍校验课程目录、公式及页码。模板降级不能提供可靠解释时，标记问题未回答并保持原阶段；不会伪装成功。

回归覆盖见 `tests/test_user_request_priority.py`：两个模式的文字/按钮推进、同轮多请求与修改、未理解片段、继续原流程、图景参考、任务完成状态、全部阶段的生成契约、无效课程引用、多问题回复和模板降级。生成接口使用本地模拟传输，未调用在线模型或部署服务。

运行：

```powershell
$env:PYTHONPATH='src'
$env:PYTHONIOENCODING='utf-8'
.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider --tb=short
```
