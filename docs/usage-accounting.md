# 回复用时、设计用量与经验提炼费用

两个 mode 使用同一计量链路。每条在线 Agent 回复右侧展示服务器实际处理用时，工作区标题右侧显示该设计的累计对话活跃时长。页面空闲、用户输入、请求进入处理前的排队，以及反馈队列等待均不计入；累计值不是“创建到现在”的墙上时间。等待模型返回属于本轮处理时间。时长在处理完成后更新，不靠浏览器定时器累计，刷新和恢复设计沿用后端记录。

维护者审阅页的“设计用量记录”按钮读取受维护者令牌保护的 `/v1/feedback/usage?offset=0`，每页 50 个设计，显示创建时间、mode、输入/输出 token、估算 USD 费用、活跃时长和调用数。每个设计分列对话、经验提炼、设计关联翻译及合计。标题旁只显示对话时长，维护者合计包含三类工作实际处理时间之和；并行任务的处理时间分别累计，不代表一个人经过的墙上时间。设计关联翻译包括动态界面翻译和英文导出；没有设计归属的公共页面/维护者页面翻译不分摊到学生设计。

“全部反馈”和候选/已启用经验卡片同时显示对应反馈的提炼用量，包括此前失败和重试。重复经验的反馈仍在自己的反馈记录中计费，不把不同反馈的费用混为一条经验。重试和备用 API 的实际消耗都累计；重复请求返回已缓存结果时不重复记账。拒绝的 JSON 若供应商已返回 usage，仍记录消耗。供应商未返回 usage（例如网络中断）时不会把预留输出额度当作实际消耗。

## 后端环境变量

新增可选变量 `ECE329_MODEL_PRICING_JSON`。默认 `{}`：仍记录 token 和时长，费用显示不完整，不能理解为免费。按你的 API 账户/代理实际单价填写；所有金额统一为 USD，每百万 tokens。推荐键格式为 `openai/实际API模型ID` 或 `deepseek/实际API模型ID`，优先于旧版不带服务商的模型键，避免不同 API 使用同名单价。不是前端展示名称或 fast/reasoning 预设 ID。

以下只是计算格式示例，**不是官方现价**：

```dotenv
ECE329_MODEL_PRICING_JSON={"openai/your-openai-model-id":{"input":2,"cached_input":0.5,"output":8},"deepseek/your-deepseek-model-id":{"input":1,"cached_input":0.1,"output":2}}
```

每个模型必须包含三个非负数：`input`（未缓存输入）、`cached_input`（缓存输入）、`output`（输出，含供应商计入输出的推理 token）。单位均为 USD / 1,000,000 tokens，不是每千 token，也不是账户余额。可以在同一对象中加入多个模型。

计算：`((输入 token - 缓存输入 token) × input + 缓存输入 token × cached_input + 输出 token × output) / 1,000,000`。输入 1000、缓存 200、输出 100，以上示例得到 $0.0025。缓存输入不会重复按普通输入收费。每次调用保存当时的单价快照；之后调整价格不会重算已有记录。缺少价格、缓存明细或 token 时保留已知部分并标为不完整，实际扣费仍以服务商账单为准，不会声称读取了账户余额。

仍需 `ECE329_FEEDBACK_ADMIN_TOKEN` 用于维护者查看，以及 `ECE329_DATABASE_PATH` 指向持久磁盘。无需新 API 密钥，无需删除数据库：启动时自动增加 `usage_designs`、`usage_runs` 表。须同时部署前后端并重启后端。

## 存储与边界

- 新建设计即注册用量账目；后续处理逐次累加。旧设计仅从升级后的处理开始记录，标为历史不完整，不补造过去的 token、时长或费用。旧聊天消息缺少用时会显示“未记录”。
- 原有失败反馈的历史尝试若未计量，即使后续重试已计量，累计费用仍标为不完整。
- 普通异常退出会记录已取得 usage 的调用。进程被直接终止、供应商未返回 usage 或存储不可用时不能恢复精确消耗；本功能不是与供应商对账的财务账本。
- 记录不保存 API 密钥、完整提示词或模型推理文本。设计删除或会话 TTL 到期会一并删除关联用量，遵守现有设计保留规则。持久化数据库重启后保留记录；内存模式会丢失。
- 费用和时长计量不改变阶段推进，不增加模型调用，不修改既有十次反馈尝试上限。

回归入口：[后端计量测试](../tests/test_usage_accounting.py)、[显示格式测试](../tests/frontend/usage.test.cjs)、[维护者界面测试](../tests/frontend/feedback-review.test.cjs)、[浏览器端到端验证](../tools/verify_usage_browser.cjs)。浏览器使用本地 SQLite 与固定 usage 的模型替身，不调用付费 API。

## API、agent 与阶段明细

维护者设计卡片和经验卡片均可展开“按阶段、Agent 和 API 模型查看”。记录区分设计 Agent、意图解析、经验提炼、经验检查及翻译；这些是应用内调用职责。每组标明实际路由的服务商、请求的 API 模型 ID，以及服务商返回的模型 ID（若返回）。选用的前端预设 ID 也保存在分组的 selected_models 中，不把预设名冒充 API 模型名。

OpenAI 读取 Responses usage 的 input_tokens/output_tokens；DeepSeek 读取 prompt_tokens/completion_tokens/prompt_cache_hit_tokens，再由适配器归一化。原始 DeepSeek 字段也只在已判定 DeepSeek 服务商时接受；不会把另一服务商的字段猜成自己的用量。reasoning_tokens 是输出 token 的子集，仅记录、不重复加价。缺少 usage 仍显示不完整。

每轮记录初始阶段、实际处理阶段和结束时阶段。列表另读取已保存设计的当前阶段、状态、版本和 mode；未完成表示仍可继续，不把页面闲置推断为用户主动终止。最近处理失败不会被翻译或经验提炼的成功覆盖。阶段统计按实际 API 调用所属阶段拆分，跨阶段修订、路由升级和重试都归入实际调用位置；经验分析归入反馈目标阶段，翻译归入请求时的设计阶段。

阶段/模型明细显示 API 调用用时；整轮解析、保存等无法精确归属阶段的其余时间单列“未分配的本地处理”，不把整轮耗时重复分配给多个模型。阶段汇总与 agent 明细是同一份消耗的两种视图，不应相加。旧记录缺少阶段或 agent 字段时标为未记录，不反推填造。

本次验证：全量 1351 项测试、210 个子测试通过；随后补充“当前阶段不被反馈成功覆盖”的案例，计量专项 20 项通过。前端计量与审阅 10 项通过；两个 mode 的桌面、手机、刷新恢复、中英文、维护者阶段/API/agent 明细和退出清屏通过浏览器验证。89 个本地文件引用、255 个 Python 相对导入无断联，Python/JavaScript 语法与 git diff --check 通过。
