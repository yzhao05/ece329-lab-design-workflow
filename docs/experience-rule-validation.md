# 经验规则：可信验证、受控配置与模型评测

## 实施结果

1. 覆盖报告逐项列出声明与实际测试的模式/阶段、应触发且实际执行的正例、不应触发的反例、分别通过数量及未覆盖范围。默认 264 个固定场景；每个声明范围至少 2 个中英文正例与 8 个边界反例。有附加条件时再回放条件不满足的场景。覆盖不足返回 `insufficient_coverage`，审批拒绝执行能力。
2. 各规则先独立判断适用条件；仅对当前适用规则比较规范化后的实际动作。不同重复次数门槛不构成写入冲突。旧版省略的必要缺项询问和新版显式动作等价，合并执行且保留所有来源。不同回复写入参数等真正冲突阻止经验修正，保留用户的明确意图走基础流程；不再强制改成 UNCLEAR。
3. 回复不再仅做文字追加或字符串去重。执行结束旧候选后，从当前有效待办、阶段校验及已完成动作渲染受控回复；缺项问题使用本地缺项处理器。验证待办引用、正文任务一致、旧候选结束及数据保留。没有可验证任务时不能声称执行通过。最多修正一次。

## 维护者操作

1. 在经验审阅卡中展开“结构化条件与受控动作”。必要前提始终是：存在未提交候选、明确拒绝并要求继续、本轮无新修改。可多选待办类型限制和配置最低重复次数；不选类型表示不增加类型限制。手动更改 JSON 后，先用“从当前 JSON 载入结构化设置”同步，避免旧设置覆盖新条件。
2. 选择回复方式“已完成动作与下一步任务”或“只显示有效的下一步任务”，生成结构化草案。阶段不完整时询问具体缺项是必要行为，不能关闭；旧 JSON 省略此动作也不表示关闭。新的结构化草案明确保留它，旧 API 请求尝试关闭会收到错误说明。
3. 核对差异并应用。编辑器与 JSON 分开，生成草案不覆盖生效版本；JSON 或范围变化时需要明确处理冲突。
4. 将不能转换的文字限制写入“尚未转换的文字限制”。非空不能批准执行；可以去掉 execution 继续作为建议类经验。程序不会把任意 trigger 文字当作已实现的条件，也不会自动理解未登记的任意限制，维护者必须逐项核对实际执行条件。
5. 回放当前 JSON，检查覆盖及断言结果，确认实际执行条件，然后批准新版本。批准绑定当前 JSON、范围、来源版本与验证器版本 4。修改后旧验证不能再批准新内容。

动作库目前开放结束被拒绝候选、重新检查阶段、具体缺项追问、受完整性和确认约束的推进、受控回复校对。组合必须保留安全前提和必要动作顺序。关闭任意已回答待办、补答任意遗漏问题仍不支持，未知动作明确要求代码维护；不是任意工作流脚本编辑器。

## 三层结果

| 层次 | 实际运行内容 | 未运行或证据不足 |
|---|---|---|
| 执行器测试 | 给定模拟语义，运行真实本地工作流和程序断言 | 未测试或覆盖不足 |
| 模型语义评测 | 明确点击按钮后，调用配置的经验模型识别自定义正反例及中英文边界反例 | 未测试；不会借用执行器结果 |
| 历史完整流程回放 | 从实际问题前快照开始，使用本次模型分类进入隔离执行和本地回复，比较无规则/有规则结果 | 无前快照为 unavailable；条件不符为 not_applicable |

语义评测使用专用结构化分类请求；示例的人工正确标签不发给模型。自定义案例在每个声明模式的第一个声明阶段评测，不声称其真实模型语义覆盖了所有阶段。完整流程回放的回复由本地工作流和受控渲染器产生，不是生产 Agent 所有请求的完整在线重跑。普通“隔离回放当前 JSON”仍只使用模拟/已记录语义响应。

评测每个来源版本最多 3 次（失败也占次数），每次 1 个请求、最多 8192 输出 token、64 KB 输入，不自动重试。请求及返回用量计入原反馈，标记提供商、模型与评测用途；缺失用量不伪装成 0。模型响应缺项、错误引用或无法解析时记失败，不泄露原始异常正文。持久化失败记录关联 ID。反馈提炼的十次上限不变。

维护端“经验执行记录”提供最近 1000 轮按规则/版本/模式的统计。等效规则合并后，验证结果归属全部来源规则，单轮同一规则/结果只计一次。通过率的分母仅是执行验证结果；相关性、预算、条件不符、冲突等分别计数，不把检索、注入、语义评测和线上断言混为一个成功率。

模型评测另行汇总“模型判断后的受控流程检查”：即使语义分类通过，流程执行报错也明确显示未通过。历史回放出错不能标记成“不适用”。自定义示例和固定边界示例即使文字相同，也保留各自来源分类。

## 部署

同步部署后端和前端。后端启动幂等新增 `experience_evaluations`；已有经验、审阅和状态不被改写。新审批重新运行版本 4 验证并确认条件。真实模型评测复用现有经验模型配置，只有维护者点击才产生请求。无需新建 Agent 或新密钥。

最新兼容修复验证结果：后端全套 1606 项测试及 212 个子测试通过；前端 154 项通过。真实 Chrome 本地夹具验证了多选条件、草案冲突、必要行为说明、条件确认、显式评测按钮、分层结果、中英文切换、回放审批与窄屏布局。详细发现见 `experience-compatibility-fixes-2026-09-22.md`；此前复审见 `review-rule-capabilities-2026-09-22.md`。

本次开发测试使用模拟提供商，没有实际消耗在线模型额度，也没有推送或部署生产环境。模型识别效果仍需维护者运行真实评测；不能用这些模拟通过结果冒充线上语义质量。
