# 经验兼容改动后的项目复审

## 范围

检查前序规则合并、内置指导预算、结构化编辑器、审批与回放、用量记录及工作流调用链；运行全量后端和前端回归、编译、页面本地引用与脚本语法检查。关键回归使用 Guided 和 EMVR，两种模式共用后端修正。本轮没有修改生产数据库或调用真实付费模型。

## 本轮新增修正

1. **生成提示词混入回放快照**：`build_prompt_packet` 的历史清理原先仅移除 `feedback_state_before/after`，新增的 `experience_replay_before/intent` 仍进入常规生成上下文。现过滤全部 `experience_replay_` 历史字段，避免重复带入旧状态与旧语义；持久历史和隔离回放证据不变。两种模式都验证了证据仍保存、提示中不含这些字段。
2. **等效规则更换来源可绕过防重复守卫**：旧守卫只绑定主规则 ID/版本。现绑定规范化执行动作与业务状态，保留最近 16 个指纹，并兼容旧守卫。合并来源顺序改变、换成等效新 ID、只增加版本号，不能重启同一状态的修正；实质候选变化仍能执行。同轮意图适用选择也只能完成一次。该限制针对经验自动修正，基础流程仍保留用户意图和原有检查。
3. **实际注入统计可能误报**：旧逻辑仅搜索整个请求中的规则 ID。现在只核对意图 JSON 或生成请求 `CONTEXT_JSON` 顶层的 `feedback_guidance.rules`，要求完整规则内容一致；引用中的 ID、历史中的规则、截断内容和不同版本不计为注入。兼容真实提示构造函数，不保存请求原文，不改变 token/费用计算。

前序三处兼容修复继续保持：适用后合并等效执行动作；相关 FB 内置指导与学习经验共享预算；缺项询问为必要行为且前端不再提供关闭开关。新旧规则原始 JSON 不因运行时规范化而改写。
