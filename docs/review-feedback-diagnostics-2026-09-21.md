# 经验提炼诊断审阅（2026-09-21）

审阅范围：项目全量回归、前端资源引用与语法、反馈提交/提炼/审阅/检索链路，以及本次新增的诊断、用量信息和双语显示。模型请求使用测试替身，不验证线上账户余额或真实服务商可用性。

## 本次发现并修复

1. 人工重试的 payload 包含历史 analysis_attempts，之前整包进入模型输入。新增诊断与用量信息会扩大重试上下文，并可能混淆原对话证据和事后提炼过程。改为明确选择分析材料，数据库和原始 JSON 仍保留完整记录；测试验证失败后再次请求的事实输入不因诊断记录增加而变化。
2. 旧记录的 event_chain、recent_turns、analysis_attempts 为 null 时，列表拼接、证据引用收集或保存尝试可能异常。增加空字段兼容；未记录的内容保持缺失，不自动补猜。
3. 服务商响应的 output/content 为 null 或 output_text 类型不正确时，可能以 TypeError 被误报为后端代码错误。现先验证响应容器类型，归为“解析草案失败 / API 响应结构不符”。独立的程序 TypeError/KeyError 仍归为后端异常。
4. 维护者页面切换语言时会重新创建证据区域，导致已展开的诊断详情收起。将展开状态归属到当前证据记录，切换语言保留，换记录隔离。
5. 浏览器脚本仍依赖旧的“等待审阅”和鉴权错误内联文案；同步为“已生成经验”和密码错误弹窗，避免验证脚本因旧界面断言挂起。

## 两种模式与重试约束

- Guided 和 EMVR 共用反馈服务，无模式专属的诊断绕行分支。
- 测试覆盖两种模式的提交、失败诊断、人工切换服务商、历史空字段、重试输入及十次总上限。
- 不新增模型请求，不进行递归修复；自动备用服务商与人工重试共享持久化次数上限。
- 已被接管或删除的任务不能写回或启动备用分析；数据库故障沿用有限次 worker 恢复与关联日志。
- 提炼不改变设计版本或直接启用经验；经验仍需维护者批准，停止后不再被检索。

## 验证结果

- 全项目基线：1460 passed，212 subtests passed。
- 本次修复及新增用例后的重点回归：279 passed，2 subtests passed。
- 前端：117 passed。
- Python 编译、全部前端 JS 语法及 HTML 本地脚本/样式引用检查通过。
- 浏览器已验证两种模式下失败后显式切换 DeepSeek（2/10 次）、设计版本不变、窄屏与英文界面；维护者证据验证包含中英文诊断、展开状态保留、审阅草稿、JSON 复制/下载。

这些验证覆盖已定位的异常和有限重试机制，不代表能保证任意模型都生成语义正确的经验。历史记录缺失的具体原因不能追溯补造；线上 API 可用性仍以实际新请求诊断为准。
