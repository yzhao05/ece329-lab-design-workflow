## 复现和修复

新增回归最初复现十个失败案例，扩展为十七项检查。主要修复如下：

| 问题 | 当前处理 |
| --- | --- |
| 修改栏目时，同栏目的参考请求被去重删除 | 只合并冲突的写入动作，保留参考、提问、总结和未解析内容。 |
| “这样修改合适吗”“不要直接删除”被当成执行命令 | 明确讨论和否定句保持原值；明确替换才写入。 |
| 同轮两次替换保留了旧值 | 对有明确引号边界的替换依次处理，最后一次有效替换生效。 |
| 过多问题导致一次请求串行调用模型过久 | 每轮最多处理十六个问题，保存剩余问题；用户说“继续回答剩余问题”后继续。保留外层上下文和原阶段待办，不自动无限重试。 |
| 无效几何参数仍被接受 | 长度必须为有限正数且带单位，匝数为正整数，端点不能重合。简短补填无效时不写入；更正时保留其他常量。 |
| 数值方案只有 RK4、种子数量和步数，无法复现 | 对话补全与直接 Builder 导出共用源路径分段、求积、种子坐标或生成公式、零场处理检查。 |
| 候选方法摘要带入最终实验没有选择的观察范围 | PDF 方法摘要引用最终 Student tasks，并使用当前确认的自变量和观察量。 |
| PDF 单位向量帽号可能丢失 | 常用单位向量转为 r_hat、x_hat、y_hat、z_hat，避免改变公式含义。 |

此前的跨阶段栏目同步、多问题分别回应、元问题保留待办、流程恢复和最终导出重试保护继续由回归覆盖。数值补全新增要求同时写入 Unity 构建默认方案；默认方案批准指纹变化后，需要重新审阅该方案。

旧的“追加容差保留模型”测试补全了源积分和种子位置，仍检查追加后原模型完整保留。没有通过放宽导出检查来让测试通过。

这些保护覆盖可复现的问题类别，不意味着规则解析能理解任意自然语言，或文本检查能证明物理模型、数值收敛和实际软件实现正确。

## Builder 从零构建检查

使用正式状态机和正式 PDF 导出路径生成闭合圆环磁场合成案例，提供本机 BuilderPack 定位、项目版本与依赖读取、场景对象、桌面/XR 操作、Common 接口与领域适配职责、七步实验流程、快照与恢复、Reset、取消旧计算和验收说明。

数值内容包含圆环参数化、512 源段中点积分、二十个种子的具体位置公式、RK4 步长、源排除区、零场和终止条件、有限精度复算及容差。新增要求说明形状切换后如何重建源节点、种子和恢复记录，防止沿用旧形状缓存。

本样例已具备开始编写 Unity 实现所需的设计输入和搭建说明。Builder 仍须在包内实现计算和适配代码，再编译并完成桌面/XR 验收。缺少源几何或采样定义的其他实验会被要求补全，不能以这个样例替代其设计。合成会话的确认仅用于测试，不代表真实用户批准或 Builder Gate 批准。

复现命令（项目依赖安装后，在仓库根目录）：

```bat
set PYTHONPATH=src
python -m tools.export_emvr36_review
```

输出为 `output/pdf/emvr36-biot-savart-builder-review.pdf`，中间输入在 `build/emvr36-review/`。生成目录被 Git 忽略，推送后可用脚本重新生成。
