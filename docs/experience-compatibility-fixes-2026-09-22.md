# 新旧经验规则兼容修复

用户提供的三处问题均确认存在，Guided 和 EMVR 共用修复。

## 1. 先筛选适用规则，再判断写入冲突

原来的执行指纹仍包含条件和冗余动作。现在每条规则先独立判断模式、阶段、语义及状态条件，只有适用规则才参与动作比较：

- v1 没有显式 `ask_missing_fields`，但原有 `ensure_next_task` 已要求具体缺项问题。将其规范化为与默认 v2 相同的有效动作计划。
- 重复次数 0/2 等适用条件差异不再作为动作冲突；不满足条件的规则不参与合并。
- 相同有效动作只执行一次，保留全部来源规则 ID/版本；已批准原始 JSON 不被改写。
- `status_and_task` / `task_only` 等实际回复写入要求不同仍视为冲突，保留用户意图进入原有受约束基础流程。
- 没有新增动作或放宽完整性检查，沿用执行前版本/停止检查、单轮上限和无进展守卫。

## 2. 内置指导与新经验共同控制预算

删除新格式经验提前返回的逻辑。相关 FB01–FB05 指导优先保留，再按检索排序装入完整经验，按 ID 去重，共同使用 `ECE329_EXPERIENCE_MAX_CANDIDATES` 与 `ECE329_EXPERIENCE_TOKEN_BUDGET`。

检索和提示组装复用同一预算函数；被排除的学习经验不进入执行器。记录预算/数量排除原因，不能通过删去例外来塞入经验。旧短文本接口继续保留原有字符上限。保留 FB 指导不会自动执行其中的文本，状态修改仍需程序检查。

## 3. 移除无效的缺项询问开关

缺项询问是必须行为，因此前端不再提供可关闭复选框，中英文界面及审批预览明确说明。旧 JSON 缺少该动作不表示关闭；新结构化草案明确列出该动作。旧客户端显式请求 `ask_missing_fields=false` 会得到清楚的错误，不静默忽略。

新模型草案提示也不再建议省略该动作。旧审批 JSON、版本及审阅记录保持原样；新的审批使用验证器版本 4，必须重新回放当前草案、范围和版本。

## 验证

针对性后端 61 项通过；全量后端 1606 项测试及 212 个子测试通过（637.16 秒），最终提示载荷清理另复测 18 项兼容用例通过；前端 154 项通过。以上后端数字不相加。浏览器验证了必要行为说明的中英文切换、无关闭开关、多选条件、草稿保留、回放审批及窄屏。Python 编译、前端脚本语法和 Git 差异检查通过。

全量日志：本地 `.test-tmp/experience-compatibility-full.log`；前端日志：`.test-tmp/experience-compatibility-js.log`。临时日志不提交。

本次使用纯内存工作流及模拟提供商，没有调用真实付费 API，没有更新生产数据，也没有提交或推送。需同步部署后端与前端，已启用兼容规则在下一轮按新合并逻辑处理；编辑并重新批准规则需要版本 4 的回放结果。
