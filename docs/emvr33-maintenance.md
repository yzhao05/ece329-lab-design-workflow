# emvr33 工作流修复记录

本次依据 emvr33.md 对话记录和 emvr33.pdf 第 6、8 页批注，修复“字段归属与派生内容不同步”这一类问题。附件仅用作故障证据，没有执行其中的 Builder、Unity 或阶段批准指令。

## 问题与修改

| 复现场景 | 原因 | 修改后的行为 |
| --- | --- | --- |
| 补充常量、数值算法或通过条件时要求“给我参考”，收到旧的流程或曲线介绍 | 参考仅按大阶段生成；只检查回复长度，没有检查当前待答字段 | 参考绑定 pending action 的实际 answer field；点电荷常量、积分方案、通过条件和报告问题提供对应草稿。未知物理模型只展示补充结构，不冒充已完成的可采纳方案 |
| “采用”没有完成写入，或进入了显示要求 | 参考与待答字段脱节，阶段对话记录被作为报告内容 | 采纳提交已展示的字段草稿；阶段审计记录与正式报告分离 |
| PDF 第 8 页出现旧 Initial/Reset、算法、“采用”等大段拼接 | 显示要求直接来自本阶段全部输入 | 显示要求从具体字段生成；旧会话只剔除可识别的串栏记录，保留独立的有效显示要求 |
| 已取消空间探针，基准状态和流程仍保留旧探针、曲线 | 历史阶段输出嵌入了旧 Initial/Reset；二次导出继续沿用旧派生段落 | 重新投影基准配置、控制条件、流程和默认契约，统一使用最新 Initial 与测量定义；比较保留快照，清理由显式 Reset 执行 |
| 后期改过的字段在学生报告与 Builder 文档中不一致 | 阶段状态和 EMVR 字段状态使用不同优先级 | 阶段写入同步到共享的 EMVR 字段；跨写入路径的补充、替换、清除和恢复使用当前值 |
| Builder 中显示要求未写入，只重复测量定义 | `visualization.requirements` 错绑到测量契约 | 显示要求与指标、探针定义分别导出，保留已确认的布局与比较要求 |
| 长段落中间截断，后续步骤丢失 | 字段写入和旧版快照标准化存在字符数、条目数截断 | 完整设计字段、列表和快照不再静默截断；展示精简不改变持久化内容 |
| 默认方案第 3 条过长；请求提炼后又重印全部 | UI 区域说明复制了完整参数和测量契约 | 第 3 条只列五个区域职责；参数、测量各自保留完整专栏；指定条目的总结只返回该条，不自动批准或推进 |
| 在通过条件中新增远／中／近，但没有具体距离也能完成 | 分组检查只看较早阶段，且依赖排列顺序 | 同时检查流程、预期结果、通过条件和报告问题；缺数值时只追问该缺口 |
| 同号／异号比较步骤要求“保持电荷类型相同” | 通用步骤把待比较条件也写进固定输入 | 比较步骤明确只改变待比较条件，保持其余输入及观察方式一致 |

## 验证

- `tests/test_emvr33_regressions.py` 覆盖参考与采纳闭环、只读参考、串栏、旧会话保留、重复导出、双写入路径、长字段、分组检查与单条总结。
- 使用项目虚拟环境运行全套测试：`PYTHONPATH=src python -m pytest -q -p no:cacheprovider`。
- 最终结果：617 项测试、205 个子测试全部通过；`git diff --check` 通过。
- `tools/export_emvr33_regression.py` 生成采用“无空间探针、仅定性比较”的合成会话，刻意保留旧阶段输出及污染审计记录，再导出学生版和 Builder 版 PDF。
- PDF 验证产物位于 `build/emvr33-regression/`。已检查实际页面渲染与文本，显示要求、测量定义和算法各自成栏，基准及流程不再保留旧探针。

这些验证使用本地规则生成器，不调用在线模型；合成 PDF 不是对原始会话的重建或用户批准记录。本次修改设计工作流代码，没有部署线上服务或修改 Builder Pack。
