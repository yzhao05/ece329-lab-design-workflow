# 两种模式中的对话元问题

用户反馈：修改过程中询问“你现在在问什么问题，明确告诉我”，助手没有回应。之前的 emvr35 修复仅在 EMVR 分支中覆盖了一个狭窄入口；引导模式和其他表达仍会进入实验内容解析。

## 行为

引导模式和 EMVR 模式现在共用 `meta_dialogue.py` 与引擎中的只读回复入口，处理关于当前问题、进度、修改记录、卡住原因、如何作答和模式区别的常见中英文提问。例如：

- “你现在在问什么问题，明确告诉我。”
- “我有点乱，你现在需要我回答什么？”
- “先别继续，我们现在到哪一步了？”
- “为什么你又问这个问题？”
- “刚才修改了哪些内容？”
- “我该怎么回答？”
- “引导模式和 EMVR 模式有什么区别？我们现在是什么模式？”

回复直接读取已保存的待办问题和对应字段，使用页面的七个公开阶段编号；阶段 1 的具体整理内容优先由当前待办说明。修改回顾使用保存的版本差异，不从助手语气推断哪些内容已经写入。完成检查有明确错误记录时可展示该记录，否则不编造卡住原因；没有问题或历史时明确说明。

## 状态边界

只读元问题在实验解析、候选采用、阶段推进和完成会话重开之前处理，不依赖在线模型。它只保存一轮对话及其幂等缓存，不写设计字段，不批准候选，不改变阶段、报告源数据、版本或原待办。携带旧“继续”按钮也不会推进；在引导模式中询问 EMVR 的区别不会切换模式。

旧待办的迁移只在会话副本上进行。展示过元问题后，实际答复和确认仍使用原待办及批准标识。已完成的会话回答进度问题时保持完成状态。

课程物理问题、被引用在修改值里的问句，以及包含明确字段修改/参数值的混合请求保留原处理路径；两个模式的共享提示词要求分别回答元问题并执行明确修改。此项的确定性保证针对识别到的独立元问题，不宣称任意混合自然语言或服务故障都能正确解析。现有安全边界保留。

后续复核增加分句检查：例如“我有点乱，电流方向反过来试试”不能只识别前半句并吞掉实际修改；包含实质内容的消息继续走原解析路径。复核结果见 [emvr35 项目复核](emvr35-project-review.md)。

更新并重启后端即可生效，无需用户使用特殊命令；持久化旧会话也使用同一入口。新增 `tests/test_meta_dialogue.py` 验证两模式的只读性、公开阶段编号、连续追问、缺失记录、旧待办、版本回顾、幂等重试、完成状态、真实后续填写和 EMVR 批准后导出。
