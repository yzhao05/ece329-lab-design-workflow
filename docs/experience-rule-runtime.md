# 受控经验规则、审阅草案与隔离回放

本次提供 Guided/EMVR 共用的最小执行闭环：用户语义明确表示不执行旧候选、保留已保存设计并继续时，结束未提交候选，重新检查阶段，并在正文提出下一步问题或通过原有检查推进。不是任意自然语言修补代码的平台。

## 规则与权限边界

旧经验 JSON 不变，继续作为建议；没有自动推断执行动作、前置条件或验证结果的迁移。可执行经验额外包含 `execution`。规范模板由 `experience_rules.contract()` 提供，包含版本、语义意图、四类例外、四个执行环节、动作与参数、前置条件、结果断言、冲突策略、执行/修正上限和正反例。模式/阶段仍为原规则字段，范围继续由审阅接口审批。

第一版只允许完整的 `KEEP_CURRENT_AND_CONTINUE` 动作组合：

- `decline_uncommitted_candidate`：源文本覆盖完整本轮，模型明确给出 KEEP_CURRENT + ADVANCE，置信度达标，没有新修改或未解析动作，且确有未提交候选。
- `recheck_stage`：复用 `WorkflowEngine._validate_completion`。
- `advance_if_complete`：由原状态机执行，推进前再检查；不直接写阶段编号。
- `ensure_next_task`：最多一次本地修正，将已有有效任务或后端生成的具体问题放入正文，不调用模型重写事实。

任意代码、SQL、未知函数/动作、额外参数、删除例外、削弱前置条件或扩大次数上限均被拒绝。尚未支持通用的“凭回答证据关闭任意重复待办”等动作；尝试添加时返回需要代码维护，而不是声称已经实现。内置的明确拒绝旧候选处理继续保留；回放基线可能已经正确，这时不得把相同行为全部归功于规则。

四个统一检查点为意图判断后、待办处理前、推进前和回复保存前。待办变更同时更新对话主记录、设计状态投影和 carried context。验证检查旧候选结束、既有内容保留、历史保留、阶段检查、具体任务及不重复旧问题。验证破坏既有内容时在最终保存前失败关闭，保留数据库中的已提交设计。

同一规则 ID/版本/业务状态单轮最多执行一次，回复最多修正一次；无进展状态记入会话守卫，下轮相同规则/状态不得再执行。不同规则的写入契约不一致时全部阻止，相同契约合并执行，始终保留规则 ID/版本。规则执行前重新检查已启用版本。反馈提炼仍沿用原 10 次总尝试上限。

## 审阅操作

1. 填写原不当内容、人工修正内容、处理意见；无需修改时前两项可留空。
2. “根据审阅意见生成修订草案”复用已配置的经验提炼提供商，只调用一次模型，不自动重试。请求用量计入该反馈原有用量统计；未知用量仍为 null。
3. 草案和变更字段独立展示。只有明确点击应用才复制到 JSON 编辑器。生成期间手动改过 JSON 时，必须手动合并或再次明确选择替换；当前生效版本始终不变。
4. 可执行规则先点击“隔离回放当前 JSON”。验证 ID 绑定来源版本、完整 JSON 和 scope；修改任何一项后旧验证不能用于批准。
5. “启用经验”或“批准修订并启用”以乐观版本检查保存新版本和审阅来源。停止和并发审批也使旧草案版本失效。恢复历史版本只生成草案，仍需检查、回放及批准，不撤销过去的用户设计修改。

记录刷新、展开收起、语言切换保留当前页面审阅草稿。维护者令牌不保存。生成过的草案另有后端审计记录。原始 JSON、输入框和原始证据不被界面翻译改写。

## 检索、预算与记录

先过滤启用状态、模式、阶段和权限范围；关键词/类别排序结合候选修改和重复待办的结构化状态，不再按更新时间兜底。受支持语义意图由既有模型解析，跨语言只影响模型输入理解，后端执行判断使用相同结构化动作，不用“继续”等关键词修改状态。第一版不引入向量索引，不能保证任意旧建议都能跨语言召回。

| 配置 | 默认 | 上限 |
|---|---:|---:|
| ECE329_EXPERIENCE_MAX_CANDIDATES | 8 | 20 |
| ECE329_EXPERIENCE_TOKEN_BUDGET | 4096 | 16000 |

预算使用完整规则 JSON 的 UTF-8 字节数作为保守 token 上界，而非声称测得精确 tokenizer 数量。超预算时整个规则排除，绝不删除例外以保留动作。记录相关性、范围、数量、预算及冲突排除原因；最多 120 条检索明细，另记录所有原因计数和省略明细数。

维护者“经验执行记录”展示检索 → 实际注入 → 适用判断 → 动作 → 状态变化 → 验证。注入只在实际请求含该 ID 时记录；没有用模型时不会伪造注入。默认显示简短结论，技术详情收起，可跳回规则审阅/停止。固定中英文映射不翻译证据。审批、注入、模型声称采用、程序断言通过是不同事件；目前未采集模型的“声称采用”，记 null。

## 回放与限制

固定隔离套件含两种模式、中英文、完整/缺项及四类反例共 72 个场景，包含全部 13 个内部阶段。运行真实工作流代码、内存设计库和模拟语义响应；不调用在线模型、不写真实设计、不导出文件或触发部署。对比无规则与有规则时的状态、回复及程序断言。旧 Guided 子阶段归并回想法完善不算向前推进；向前推进必须经过实际的推进前检查。

验证记录同时绑定验证器版本。升级后，旧验证器的结果仍保留用于审计，但不能用于新的审批，必须重新回放。历史状态没有旧候选时按不适用处理，不误报执行失败；损坏或不完整快照标记无法完整回放。

新轮次保存发生前的必要会话状态及语义解析结果；不保存鉴权令牌、服务商上下文或缓存。历史中的 replay 字段不递归复制；快照超过 96 KB 或包含凭据字段时记录不可回放原因，不截断后声称完整。缺失问题前快照或当时语义响应的旧记录明确为无法完整历史回放，不使用提交时快照替代。

实际历史状态回放仍使用已记录语义响应和本地响应生成器，属于“记录响应隔离回放”，不是真实模型重跑。固定模拟套件通过可授权该受控契约，但不代表自定义正反例已经通过模型语义评测。真实模型对照和线上结果分别标识；本次没有在线模型实测。

## 部署

初次实现的后端全套 1557 项测试及 212 个子测试通过；后续审阅的结果见 `review-experience-rules-2026-09-22.md`。真实浏览器夹具验证了草案生成、JSON 冲突提示、刷新保留审阅内容、中英文切换、回放批准及窄屏布局。浏览器夹具使用模拟提供商，未测试线上模型或生产部署。修订草案费用计入原反馈，但不会用于补足缺失的历史分析尝试用量。

后端启动自动新增 `experience_drafts` 和 `experience_validations`，保留旧经验内容、状态、版本和审阅记录。无需修改已有经验或清空数据库。数据库仍应位于持久磁盘；正式更新前备份 SQLite。同步部署后端和 docs 前端，静态资源已更新版本参数。

新增两项检索配置有默认值，不设置也能运行。草案生成复用现有经验模型/API 配置，不需要新 Agent 或新密钥。GitHub Actions 已加入新前端脚本检查；main 的 CI 和容器检查通过且配置 `RENDER_DEPLOY_HOOK_URL` 后，现有部署任务才会触发后端更新。Git push 本身不代表已完成部署。

CMD 中先检查改动，再提交本次文件（不要把不相关的根目录未跟踪文件加入）：

```bat

git status --short
git add .env.example .github docs src tests tools

```

部署后在维护页加载规则 → 生成草案 → 核对 JSON/范围 → 回放 → 批准新版本，然后在原设计明确发送保留并继续的请求，并检查本轮“执行断言通过”记录；仅看到“已启用”或“实际注入”不足以确认修复。
