# Guided 图景扩容后的项目审阅

本次检查覆盖图景数据、公式与课程引用、抽样记录、会话持久化、在线输出校验和修复边界，并运行整个后端测试集、前端反馈与模型选择测试，以及模块引用和发布包检查。

最终版本验证通过：后端 1237 项测试、210 个子测试；前端 27 项测试；69 处本地文档链接、238 处 Python 相对模块引用；Python 编译、JavaScript 语法、知识库完整性和 `git diff --check`。发布包验证确认 wheel 内包含新增图景 JSON，可直接加载全部 183 个候选。

## 修复的问题

1. **同一候选可伪装成三个不同画面。** 原校验只检查每个候选是否属于检索结果；旧的通用模板能够把同一个候选渲染成三种画面。现在按稳定 `option_id` 检查批次内唯一性，同时保留跨抽样周期的顺序校验。
2. **返回对象与共享知识库共用嵌套数据。** 原浅复制使返回的图景模板、页码列表和公式档案条件仍引用共享对象。现在图景目录、抽样结果、公式绑定和档案返回独立副本，避免一次会话中的修改污染其他会话。
3. **坏目录可能直到生成回复才被发现。** 现在加载知识库时执行完整校验，直接报告错误引用、编号、范式组合或页码问题，避免把配置错误交给模型反复修复。

这些防护针对候选身份、数据所有权和目录完整性，不依赖某个具体实验的词语。新增回归测试还覆盖会话保存后恢复抽样周期，以及模型连续返回重复候选时最多一次修复、共两次生成请求后停止。

## 检查范围与边界

- 新目录保留 183 个候选、每轮三个的展示规则，原有 138 个编号与绑定保持不变。
- 抽样测试覆盖全课程池及三个课程领域，连续三个周期无提前重复；剩余一两个候选先展示再换轮。
- 静态检查验证本地文档链接、Python 相对模块引用、JavaScript 语法和 Python 编译。
- 实际构建 wheel，并直接从 wheel 导入知识库，确认新增 JSON 随包发布且 183 个图景的引用完整。
- 前端测试涵盖反馈重试、幂等提交、模型切换、语言与思考强度配置，以及两个 mode 的冲突恢复。
- 本次未调用真实收费模型、未修改线上部署、未提交或推送 Git。测试能够防止已复现的问题回归，不能证明所有未来模型回复都不会出现语义错误。
