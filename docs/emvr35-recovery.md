# emvr35：流程丢失、最终阶段无法补全与参考失效

附件 `emvr35.md` 作为用户反馈证据读取，没有执行对话里对实验 agent 的指令。本次只修改设计工作流，不改 Builder Pack，也不改线上数据库。

## 定位结果

1. 阶段 3 已展示七步实验流程。用户要求“明确写出流程中第七条的内容”后，回复把整个 `procedure_steps` 替换成第七条，并进入下一阶段。这是查看与修改、单项与整份列表的边界混淆。
2. 阶段 7 的报告校验发现完整流程缺失，但修复路由只查当前阶段，随后进入 `artifact_blocker`。用户重新提交整段、中文编号或 S1 编号的七步内容，都没有绑定到可写的流程字段。
3. 最终阶段补齐前文后，重新生成的实现默认方案可能失去具体批准值及选项标识，导致“批准默认方案”无法结束补全流程。
4. “给我个参考”未覆盖固定参考入口。测量与算法参考又缺少磁场模板；部分通用参考把上一轮未经授权绑定的反馈当作可采用答案。
5. 明确的“位置偏差小于 1%”“磁场强度相对误差小于 1%”未被容差校验接受。用户最终被迫改成单独的科学计数法数值。
6. 报告编号清理把 `0.5A`、`1.2A` 的小数前缀当成列表编号。JSON 数组字符串没有解包；磁场的“定性形态指标”也没有触发原本针对点电荷的曲线修正，造成显示矛盾。

## 修复边界

- EMVR 中明确的单步查看先走只读响应，保留待办、全量流程和当前阶段，即使请求携带旧“继续”按钮也不推进。明确改第几条只替换对应条目。
- 完整流程共用解析器，接受列表、JSON 列表、连续数字/S 编号和按中文句号分隔的步骤；保留小数、单位、顺序及重复操作。流程读取、规范化和 Builder 默认步骤使用一致的边界。
- 最终检查将前序阶段缺项绑定到真实字段；已卡在旧 `artifact_blocker` 的会话也会重新建立可填写的问题。修改后仍重新检查完整性及默认方案批准，不跳过完成条件。
- 查看历史不写入当前设计；用户明确要求恢复时才采用历史中最近展示的完整流程。没有完整历史就明确说明，并支持提交新流程或索取参考。历史展示版本不等于已核实的用户批准版本，恢复后仍需审阅。
- 后续复核限制恢复到当前实验的历史，并排除“不要恢复”等否定请求，避免换题后混入旧实验。新增回归与 PDF 构建检查见 [emvr35 项目复核](emvr35-project-review.md)。
- 阶段参考、展开和澄清回复不覆盖已保存的阶段设计产物。参考只有在绑定到具体字段并可采用时才提供采用草稿；未确定的磁场路径、种子与排除区仍明确列为缺项。
- 毕奥–萨伐尔实验的测量、数值算法和预期结果提供实质参考，区分已记录值与建议值。固定种子下不要求场线数量或环绕范围随电流增大；真正未提供模板的其他公式继续保留待填写框架，避免套用静电方案。
- 数值误差支持百分比和比较式。明确的容差补充合并到原算法契约，不丢失计算域、种子、步数和边界；它是文本完整性检查，不代表已完成数值收敛实验。
- 定性测量契约约束磁场等实验的派生报告、坐标轴与 Builder 显示策略；数值电流输入仍保留，有真实 B 分量读数的实验也不会被改成纯定性。
- 默认方案升级为 `builder-ui-flow-v6`。旧版本的批准需要重新审阅，避免旧曲线策略或旧流程继续作为有效交接契约。

## 已卡住会话的使用方法

先更新并重启后端。若会话通过 SQLite 持久化保存，可在原会话回复“阶段3的时候已经确认过实验流程”核对历史，确认后回复“恢复之前的实验流程”。也可以直接提交 `实验流程：` 后的完整步骤，支持一段文字、`1，… 2，…` 或 `S1 …；S2 …`。

修复缺项后，系统可能要求重新审阅完整实现默认方案；查看本轮具体内容后再回复“批准默认方案”。最终完成仍以全部设计字段和 Builder 校验通过为准。

若使用内存会话存储，重启会清空历史；代码不能从不存在的记录恢复。此时需重新提供步骤。维护代码不会自动恢复已经运行在其他服务器上的旧会话。

## 回归验证

`tests/test_emvr35_recovery.py` 覆盖原始单步查看、单项修改、旧最终阻塞、三种整份替换格式、历史只读与显式恢复、缺失历史、参考采用、误差补充、JSON 与小数、重复步骤，以及磁场定性报告。三种旧会话补全测试均继续执行到 `workflow_status=complete` 和 `builder_input_ready=true`。

旧 emvr33 的“无专用公式模板不得套用 RK4”样例改用法拉第微分公式；毕奥–萨伐尔现在有自己的磁场参考，新测试另查其内容不能混入库仑场或介电常数。

测试使用本地规则生成器和合成完整磁场会话；全量测试包含模拟在线 transport 与真实 PDF 渲染/文本检查。没有调用真实在线模型，也没有运行 Unity。通过这些检查不等于任意自然语言都能被正确理解，或 Unity 实验已经构建验收。

验证结果：完整套件 819 项测试、205 个子测试通过，无跳过；随后补充 v5 到 v6 的实际会话重开及重新批准回归，最终 emvr35 专项 19 项全部通过。Python 编译、知识库引用校验和 `git diff --check` 通过。PDF 相关测试使用带 `pdfplumber` 的 Python 环境执行。

运行专项回归：

```bat
set PYTHONPATH=src
python -m pytest tests\test_emvr35_recovery.py -q
```
