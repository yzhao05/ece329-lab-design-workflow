# 中英文界面与模型设置浮窗

输入框右下角以无边框文字展示当前模型。点击后展开绿色浮窗，包含模型策略、经验开关、有限升级、逐阶段设置、回复模型、刷新列表及生效提示；关闭后不占用对话区域。可通过关闭按钮、点击外部或 Escape 收起，窄屏根据可用空间调整位置、宽度和滚动区域。

浮窗也支持逐模型思考强度和动态输出限额，见 [思考强度与动态预算](reasoning-budgets.md)。

## 两种模式的语言切换

课程连接状态与“反馈问题”之间的 English / 中文按钮切换显示语言，并在当前浏览器保存偏好。GUIDED_DESIGN 和 EMVR_DIRECT 共用这条线路：

- 固定界面、占位文字、阶段、模型设置、反馈表单与状态提示使用内置英文词表。
- 创建与继续设计的请求携带 `language: "zh" | "en"`；后端将语言偏好加入回复指令。幂等重试保持原请求语言，避免同一轮重复推进。
- 历史对话、课程证据、设计内容及规则回退回复通过独立翻译接口生成显示副本。切换语言不提交设计轮次，不改变阶段、学生原始记录、字段 ID、审批或反馈经验。
- 英文模式下载学生 PDF、Builder PDF 和引导模式总结时，请求对应语言的导出副本。Builder 原始结构与完整性仍先经过验证。
- 反馈经验审阅页同样支持语言切换；正在编辑的输入值、密码、原始 JSON 不被显示翻译覆写。

## 后端与部署

前端与后端需要一起更新并重启后端。**无需增加必填环境变量**；动态翻译复用现有 OpenAI / DeepSeek 配置及模型白名单。静态界面英文不需要在线模型，动态内容与英文导出需要可用模型服务。

新增 `POST /v1/localization`：请求包含 `texts`、`language`，可选 `design_id`、`model`。有设计时使用现有会话所有者鉴权；设计开始前使用课程访问码；经验审阅页使用维护者令牌。接口受现有请求限流保护，每次最多 24 段、总计 12000 字符。客户端按边界拆分长文本，不在公式或路径标识符内部截断。

翻译会产生额外模型调用费用，服务端按模型、语言与源文本缓存；页面也缓存已翻译内容。翻译失败会明确显示失败提示，需点击“重试翻译”，不会自动无限重试。切换语言或设计后，迟到的旧翻译结果会被丢弃。

PDF 和总结下载使用 `?language=en` 或 `?language=zh`。这些是面向阅读的副本，持久化的原始设计、审批状态及机器字段不会被翻译替换。

## 验证范围

`tests/test_language_and_localization.py` 覆盖双模式语言持久化、幂等、授权、模型路由、翻译缓存、错误处理、长文本与英文 PDF。`tools/verify_language_browser.cjs` 覆盖双模式、桌面与窄屏、历史文本、刷新恢复、翻译失败重试及迟到结果隔离。既有模型、策略和反馈浏览器回归继续验证实际前后端线路。

自动化测试使用受控模型替身，不消耗真实 API 额度；英文 PDF 的排版与引用验证不代表真实模型的翻译质量或 Unity 实机运行验证。上线前可使用已配置的真实模型检查课程术语与长篇报告译文。
