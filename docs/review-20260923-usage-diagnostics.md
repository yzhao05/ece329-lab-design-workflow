# 费用移除与执行诊断审阅（2026-09-23）

本次审阅检查未提交变更、共享计量链路、Guided/EMVR、反馈提炼与工作流防重复执行机制。费用估算不再计算或显示，token、API 模型、调用次数及活跃时长继续保留；旧定价配置被忽略，历史原始记录不做破坏性清理。

## 已复现并修复

1. 恢复函数本来可以安全拒绝非法待办，但新增诊断包装器继续对字符串、列表、整数调用 `.get()`，导致异常。包装器现在使用经过类型检查的诊断视图，无观测上下文时直接返回原结果；不改变字段绑定权限。
2. 诊断把任何阶段变化都当作推进，包括旧阶段向前置阶段归一化，同时漏记“最终阶段保持原位但工作流已完成”。现在记录初始阶段索引和流程状态，仅把向后续阶段移动或实际完成流程记作成功。
3. 提炼输入的 18,000 字符限制原来只计算事件，未计算最终意图、待办和经验执行摘要。现将元数据、事件、重复引用一起计入预算，保留截断/省略标记，原始证据保持不变。
4. 无版本号的不同历史轮次原来都用 `None` 去重。现只对有确定整数版本号的轮次去重，不合并无法关联的证据。

另有 13 项原有只读对话测试把整个内部上下文视作不可变化，与新增私有诊断记录冲突。现仅允许追加 `execution_diagnostics`，继续严格比较其余上下文、设计、阶段和待办；相关 38 项测试复测通过。

## 防循环与范围

- 观测代码不触发模型请求、不自动重试、不批准修改、不绕过阶段检查。
- 经验规则已有的同状态执行拦截、版本/停止状态复核、冲突阻止与单次回复修正上限保留；冲突/版本变化/同状态无进展的回归扩展到两个模式。
- 反馈提炼及备用提供商共用十次上限；数据库故障的后台工作器保留三次连续错误退出机制。
- 这些修复防止诊断异常造成恢复失败，并提高故障证据准确性；不能据此宣称解决全部模型误判或多字段回答解析失败。
