| 问题 | 修复与验证 |

| 回复修正后历史/阶段输出仍可能保存旧待办投影 | 同步本轮回复、历史输出和阶段输出中的正文、任务和待办快照，保留之前的历史 |
| 检索后上下文发生变化，仍可能使用旧模式/阶段的规则 | 意图处理后、动作执行前重新核对规则模式和阶段 |
| 历史回放对“保留并继续但没有旧候选”误报失败 | 历史适用判断同时检查旧候选是否存在；没有候选视为不适用 |
| 损坏旧快照可能抛出后端异常；历史回放内层类型标记不一致 | 校验快照基础类型/阶段边界；损坏快照明确为不可回放，记录响应回放统一标记其类型；基线异常不能算回放通过 |
| 草案生成与应用可能覆盖维护者选择的范围 | 后端保留请求范围；前端将范围变化与 JSON 变化一并纳入冲突提示，未经明确操作不覆盖 |
| 旧验证器的结果可能继续用于新审批 | 保存并检查验证器版本；旧结果可查，但新审批必须使用当前验证器重新回放 |

## 防循环及适用边界

本次没有增加模型自动重试。受控规则单轮最多执行一次、回复最多修正一次；相同规则/版本/业务状态的守卫仍然生效。两种模式使用同一个执行入口与校验器；保留已有完整性、用户确认与鉴权检查。反馈提炼总尝试上限没有扩大。

回放测试使用模拟或已记录的语义响应。浏览器使用模拟提供商和本地测试数据；没有调用真实线上模型，没有验证生产设计记录，也没有执行生产部署或容器构建。它证明程序在已识别语义下正确处理受支持动作，不证明在线模型总能正确识别用户意图。

受控动作仍限于“明确拒绝旧候选、保留设计并继续”的闭环。其他动作必须经过后端实现及测试。已批准、已注入、模型声称采用与执行断言通过依然分开记录；不把本次审阅等同于所有潜在问题都已排除。
